# Official React SDK compatibility fixture

This fixture is built and run by `sh portal/gateway/run.sh`. Dependencies are pinned: `@documenso/embed-react` 0.6.2, React/ReactDOM 19.2.8 and esbuild 0.28.0. Installation and bundling happen inside the pinned Node container. It serves only the synthetic SDK shell; it is not the Atrium application.

The signing session is first established by entering the recipient PIN at `https://signing.growthcast.test:8443`. The browser then opens `https://portal.growthcast.test:9443` and loads the official `EmbedSignDocument` component against the signing origin. These are different origins on the same site, matching the proposed portal/signing subdomain relationship. Host-only SameSite=Strict signing cookies remain on the signing host; the parent gets no signing cookie and cannot read the frame DOM. The test supplies a recipient token in a fragment and immediately removes it from the parent address. Possession of that token alone is insufficient to load the protected frame.

The gateway permits only the session-bound `/embed/sign/:token`, its exact manifest dependencies and the previously validated API/PDF routes. It changes `frame-ancestors` only for that exact embedded response, allowing only the configured local parent. All other pages retain framing denial. Another same-site hostname is served solely to prove the browser blocks an unapproved parent. Direct-template, authoring, other-recipient and arbitrary query routes remain denied.

The SDK checks the sending Window when processing messages. The wrapper additionally checks message origin before the SDK listener receives the event. The test injects a message with the right Window but wrong origin and requires the UI to stay in its ready state. SDK events update UI only; canonical API read-back and PDF verification remain authoritative. A missing gateway session returns plain HTTP denial, which cannot emit an upstream SDK error event, so the wrapper shows a generic error after a bounded wait.

No CSS/branding overrides or paid feature flags are supplied. Existing provider branding and claims remain intact. The test uses Chromium at desktop/mobile widths and a disposable self-signed certificate, not production certificates or Safari/Firefox acceptance. SDK signature placement uses real pointer clicks at the server-bound canvas field, after checking that the field is visible and unobstructed. The mobile test collapses the signing panel before clicking the field. The native path still uses a Konva scene event; keyboard accessibility remains separate work.
