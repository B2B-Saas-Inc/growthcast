# Google Workspace SMTP for GrowthCast

The operator configured `clients@growthcast.app` as a sending alias of `ewhite@growthcast.app`, enabled 2-Step Verification, generated an app password, and saved the portal SMTP settings. Readonly inspection verified SMTP provider, `smtp.gmail.com`, port 465, TLS enabled, sender `clients@growthcast.app`, login `ewhite@growthcast.app` and a stored encrypted password. No password was printed or copied into deployment metadata.

The API was healthy when the operator reported HTTP 502. Its security group allowed only outbound 443 and 5432, preventing SMTP on 465; the proxy has a 25-second upstream deadline. A reviewed CloudFormation change added only outbound TCP 465 and preserved API ingress. `network-evidence.json` records the change. Nodemailer connection/greeting/socket timeouts now provide bounded failures, including the settings Test Email endpoint.

The application is explicitly configured with `PORTAL_MAIL_MODE=workspace-smtp` and the GrowthCast sender organization ID. This routes real application mail through that organization's encrypted SMTP configuration even before a new recipient has organization membership. The Workspace transport validates the fixed sender, Google host, login, port and TLS configuration, does not silently fall back to another provider on failure, and closes its transport after each send. Synthetic `.invalid`/`.test` recipients remain in the existing internal capture service. The original capture-only mode still rejects real recipients.

The sender password remains in the encrypted settings row, decrypted by the existing runtime auth-secret-derived key. No new cloud credential or plaintext SMTP environment variable was provisioned. Changing the app password through settings takes effect without a stale transporter cache in the Workspace delivery path.

Six additional mail tests cover pre-membership sender resolution, missing sender identity, sender/host/login/TLS refusal, failure propagation, synthetic capture in Workspace mode, and capture-only real-recipient denial. Together with the six verified-access guard tests, the image build passes 12 tests. API and web builds pass. The UI and test-email wording now say GrowthCast.

`authentication-evidence.json` verifies Google authentication and TLS from a local container without sending mail. `cloud-auth-evidence.json` records the same check from a one-off staging runtime task using the deployed image, network and restricted credential delivery. Its SMTP `verify()` call sends no message; its output contains only bounded flags/error codes. The task stops and its temporary task definition is deregistered. This verifies connection/authentication, not inbox delivery, alias rewriting, SPF/DKIM or mail receipt. Use the portal's Send Test Email to test actual delivery to the signed-in administrator.

`deployment.json` records the image and reviewed Task/Service update. Previous API/web/image/service references and the pre-SMTP network template are retained for rollback. Current service auditing uses `../https-ingress/audit.py`; no inbound SMTP or public mail-capture port is opened.
