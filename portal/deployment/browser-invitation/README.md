# Browser invitation and captured-email verification

A disposable organization owner invited a new synthetic client through the deployed People screen. The new client followed the invitation, signed up and joined the correct organization. A one-off collector retrieved the actual invitation and verification emails from the staging MailDev sidecar; both recipients and canonical links matched. A tampered verification token left the account unverified. The real captured token verified it in the browser, and a subsequent fresh login retained the verified state and correct organization.

`evidence.json` records the bounded result. This proves staging capture and browser verification, not external email delivery. No message was sent to a real inbox. The pinned upstream currently permits an invited account into the portal before verification and redirects a successful verification to `/`, rather than the confirmation page. The driver's initial confirmation-page expectation was corrected to match that observed redirect; the verified account state was independently checked. Verified-account enforcement for later document claim remains open.

`collect.py` creates an ephemeral no-ingress collector security group, admits port 1080 to the mail sidecar only from that group, and runs the pinned Bun image with no task IAM role, non-root user, read-only root and dropped capabilities. HTTPS egress is for image/log infrastructure. Selected messages are RSA-OAEP encrypted with a temporary 4096-bit public key before entering CloudWatch; the private key and decrypted links stay only in the mode-0700 temporary directory. The collector deletes exactly the two synthetic recipient's captured messages. Its task stops, task definition is deregistered, peer ingress is revoked and security group deleted. Independent API-security-group read-back confirms only load-balancer ingress on port 3001 remains. See `collector-evidence.json`.

Cleanup removed both synthetic users, memberships, invitation, projects and organization. The readonly 52-table audit found 50 unchanged tables and concurrent changes only in session/client_profile rows belonging to the retained review accounts. Those operator changes were preserved; exact global equality is deliberately not claimed. See `cleanup-evidence.json`. All local test credentials, verification links and encryption keys were removed, and the browser container was removed.

Run order: `fixture.py seed`, `browser-flow.py login`, select Clients in People, `browser-flow.py invite`, `collect.py`, `browser-flow.py verify`, `fixture.py cleanup`. The `finish` mode resumes after successful verification if the final login checks were interrupted. Fixture/network receipts must be reconciled before retrying an interrupted provisioning step.
